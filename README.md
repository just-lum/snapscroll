# SnapScroll · 長截圖工坊

> 把一整頁網頁變成一張圖或一份 PDF 的 Chrome 擴充功能。
> 自動滾動拼接、框選範圍、點選元素、手動慢滾，輸出 PNG / JPEG / WebP / PDF。
> **純本機、零依賴、不用建置 —— 載入資料夾就能跑。**

---

## 1. 為什麼做這個

長截圖這個東西，看起來簡單，實際上有幾個地方一直沒被做好：

- **拼接會錯位。** 捲動位置和實際渲染對不上，結果是長圖中間出現一條 1px 的白線，或者某一段內容重複兩次。
- **固定頁首每一屏都再出現一次。** 導覽列在二十屏的長圖裡出現二十次。
- **大頁面直接爆掉。** 一張 1200 × 60000 的圖是 7200 萬像素，瀏覽器的 canvas 有上限，超過就靜默失敗——你會拿到一個 0 位元組的檔案。
- **只有 PNG。** 要交給別人、要列印、要存檔，通常需要的是 PDF。

SnapScroll 針對這幾件事做的。而且它**不複製頁面 DOM**（那種做法會讓樣式跑掉、腳本重跑一次），只用 `captureVisibleTab` 逐幀抓畫面再拼——**你眼睛看到什麼，圖裡就是什麼**。

## 2. 30 秒上手

圖示是從程式碼生成的，所以要先生成一次：

```bash
node tools/make-icons.mjs
```

然後載入擴充功能：

1. 開啟 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 右上角打開「**開發人員模式**」
3. 點「**載入未封裝項目**」，選這個資料夾（`snapscroll/`）
4. 打開任一網頁 → 點工具列上的 SnapScroll 圖示 → 「**開始擷取**」

第一次載入 Chrome 會要求權限。它只要求 `activeTab`——也就是**你按下圖示的那一刻，才對當前那一頁生效**，不會在安裝時就取得所有網站的存取權。

也可以從右鍵選單或快捷鍵啟動：

- `Alt+Shift+S` — 開啟面板
- `Alt+Shift+F` — 直接截整頁

## 3. 它能做什麼

**五種擷取模式**

| 模式 | 說明 |
| --- | --- |
| 整頁 | 從頂端滾到底，自動拼接。最常用。 |
| 可視 | 只截當前畫面，不捲動。 |
| 框選 | 在頁面上拖曳出一個範圍，只截那塊（可以跨好幾屏）。 |
| 元素 | 滑鼠移到哪個元素上就截哪個（含比視口高的元素）。 |
| 手動 | 你自己慢慢滾，擴充功能在旁邊取樣拼接。給虛擬滾動、動態載入的頁面用。 |

**四種輸出**

- **PNG** — 無損。抓幀時也走 PNG，不做二次壓縮。
- **JPEG / WebP** — 畫質可調（30–100）。抓幀時就壓成 JPEG，記憶體用量少一個量級。
- **PDF** — A4 / A3 / Letter / Legal / Tabloid，直式或橫式，頁邊留白可調；也可以選「單頁長圖」把整頁塞進一個超高頁面（超過 PDF 的 200 英吋上限時會自動改回分頁）。

**其他**

- 隱藏固定元素（頁首頁尾只出現一次）、隱藏捲軸、等待懶載入、每屏等待時間可調。
- 檔名模板：`{date}_{host}_{title}` 之類，含 Windows 非法字元的完整清洗。
- 結果頁可以預覽、拖曳裁剪、換一種格式再存一次。
- 歷史紀錄存在本機 IndexedDB，可設定保留筆數，圖片不會上傳到任何地方。

**內建診斷**（面板下方）：

- **捲動方式 / 高度上限**兩行，直接顯示在面板上。高度上限以前只在設定頁看得到，被改小之後整頁就會被硬性截斷而沒人知道。
- **「測試滾動」**：真的把頁面滾到底再滾回原位，不截圖、不改設定。它與截圖走同一套捲動程式碼，所以它失敗，整頁截圖就一定會失敗——這比拍完十幾幀再自己發現圖是錯的快得多。
- **「複製診斷」**：把 URL、四項高度來源、視口、捲動方式、預計幀數打包成一段文字，出問題時貼給人看即可。

## 4. 幾個技術決定

### 4.1 為什麼拼接要放在 offscreen document

MV3 的 service worker 沒有 DOM，也沒有 canvas，`URL.createObjectURL` 也不存在——它根本沒辦法把兩張圖疊在一起。

所以真正做像素工作的是一個 **offscreen document**：一個使用者永遠看不到的擴充頁面。它拿到每一幀的 data URL、畫進畫布、編碼，再把 `blob:` URL 交回 service worker 去下載。

### 4.2 為什麼不建一張巨大的畫布

一張 1200 × 60000 的長圖是 7200 萬像素，光點陣圖就要 288 MB，而且拼接期間還會同時存在來源 `ImageBitmap`。Chrome 的 canvas 有單邊上限與總面積上限（Skia 內部的硬限制），超標時 `toBlob()` **不會拋錯，只會回傳 null**——非常難查。

這裡改用「**軌道（tile）**」：按 y 把輸出切成若干條，每條一張小畫布，逐幀畫進相交的軌道，滿了就編碼、釋放。記憶體峰值取決於**單條的高度**，而不是整張圖的高度。

PDF 輸出時，軌道高度直接等於頁高——**每一頁只做一次 JPEG 編碼**，沒有二次解碼、沒有額外失真。

### 4.3 PDF 為什麼是手寫的

一份「一頁貼一張 JPEG」的 PDF，規格本身就極簡。PDF 的影像串流支援 `/DCTDecode` 過濾器，意思是 **JPEG 檔案可以原封不動塞進 PDF**，不需要解碼、不需要重編碼，也不需要 PNG 那套 FlateDecode 加預測器。

所以 `engine/pdf-writer.js` 自己排物件表、自己算 xref 偏移。裡面最容易寫錯的兩件事都特別處理了：

- 偏移量必須是**位元組**位置（JPEG 是二進位，用字串長度去算一定歪），xref 每一行必須剛好 20 位元組。
- 非 ASCII 字串（中文標題）要用 UTF-16BE 的十六進位字串，直接寫進 `()` 會變亂碼。

產出之後 `verifyPdf()` 會再讀一遍自己的檔案：xref 指向的位置是不是真的寫著 `n 0 obj`？不自洽就直接報錯，不會給你一個打不開的檔案。

### 4.4 一份引擎，三個執行環境

`engine/` 底下全是 UMD 模組，同一批檔案同時被：

- **Node 測試** `require()`（`node --test`，111 項）
- **service worker** 用 `importScripts()` 載入（所以這是 classic worker 而不是 module worker）
- **offscreen / popup / options / result 頁面**用 `<script>` 標籤載入

沒有任何建置步驟，也沒有「測試跑的是另一份程式碼」這件事。捲動計劃、座標換算、分頁、PDF 位元組、檔名清洗這些最容易出錯的部分全部是純函式，所以它們**可以在 Node 裡被完整測試**。

### 4.5 固定元素與「還原」

截圖時對頁面的每一項改動都留了還原紀錄：

- `position: fixed` / `sticky` 的元素，從第二幀起用 `visibility: hidden` 藏起來——**刻意不用 `display: none`**，因為後者會改變佈局，讓頁面在滾動過程中跳動。
- 捲軸用 `::-webkit-scrollbar { display: none }` 藏掉，長圖右邊不會留一條深色軌道。
- 注入 `scroll-behavior: auto`，避免平滑滾動拍到「正在滾」的畫面。
- 記錄使用者原本的 `scrollY`，**結束後滾回原位**。

不管成功、失敗還是中途取消，最後一定跑 `AG_RESTORE`。

## 5. 已知限制

誠實清單，這些不是 bug，是物理限制或刻意的取捨：

- **虛擬滾動清單**（只渲染可視項目的那種）截不出完整清單——那些項目在 DOM 裡根本不存在。請改用「手動」模式慢慢滾。
- **捲動被自訂腳本接管的頁面**（每次捲動都被推回原位、或改用 `transform` 驅動的假捲動）會直接報 `page-not-scrollable`。這是刻意的：與其交出一張內容重複的圖，不如明白說做不到。先按面板上的「測試滾動」就能確認是不是這種情況。
- **跨域 iframe** 的內容截得到（抓的是合成畫面），但沒辦法驅動它內部滾動。
- **`captureVisibleTab` 有呼叫配額**，所以「手動」模式最快約 2 fps。位置沒動時不會浪費配額去抓。
- **超大頁面**（寬 × 高大約超過 1.2 億像素）不會產出單一 PNG——會自動切成 `_part-01.png`、`_part-02.png`…輸出。PDF 不受此限，因為它本來就是逐頁寫入的。
- **`chrome://`、擴充功能頁面、本機檔案** 不開放擷取（瀏覽器不允許，不是實作問題）。
- **網頁字型的罕見情形**：如果頁面用了非同步載入的字型，第一幀可能在字型到位前就被抓走。把「每屏等待」調高一點可以避開。
- **截圖途中請不要切換分頁。** `captureVisibleTab` 只能拍到視窗目前顯示的那一頁；控制器每幀會把目標分頁拉回前台，但你在中間手動切走仍然會打斷節奏（甚至可能拍到別的頁面一瞬間）。

## 6. 開發

```bash
node --test                 # 引擎單元測試（111 項，零依賴）
node tools/make-icons.mjs   # 從程式碼生成四個尺寸的圖示
node tools/package.mjs      # 打包成 dist/snapscroll-<version>.zip
node tools/serve-fixtures.mjs --open   # 起測試頁（http://127.0.0.1:8788）
node tools/e2e/run.mjs      # 真的開一個瀏覽器跑完整流程（需要 Playwright）
```

**測試頁**（`fixtures/`）是刻意做來暴露問題的：

- `long-page.html` — 20000px 高，每 100px 一條刻度、每 500px 一段編號。拼接有沒有空洞或重疊，掃一眼就知道。可用 `?h=60000` 加大。
- `fixed-header.html` — 上／下／右各一個固定元素，正確結果裡各只該出現一次。
- `lazy-images.html` — 內容捲到才載入，頁面會在擷取途中長高。

**E2E** 會把擴充功能複製到暫存目錄、只在那份副本的 manifest 補上 `<all_urls>`（自動化測試沒有「使用者手勢」可用，`activeTab` 永遠不會生效），然後真的截圖、真的去下載資料夾把檔案撿回來量尺寸。Playwright 不是這個專案的依賴，沒裝的話它會告訴你怎麼裝，或直接沿用隔壁專案裡已有的那一份。

### 驗證紀錄

`node tools/e2e/run.mjs` 實跑結果（**34 項全過**）：

| 情境 | 實測結果 |
| --- | --- |
| 8159px 靜態長頁 → PNG | `1779×12095`，單一檔案，12 幀拼接 |
| └ 內容正確性 | 5 個採樣點逐一命中 fixture 調色板（證明不是同一屏重複） |
| 14933px 懶載入頁 → PNG | `22138px` 高，單一檔案（循環預熱生效） |
| 5000px 頁 → A4 PDF | 3 頁，每頁一個 `/DCTDecode` JPEG，xref 自檢通過 |
| 框選 400×500 | 輸出 `593×741` |
| 可視模式 | 1 幀、不改變頁面捲動位置 |
| 擷取後的頁面狀態 | `scrollY` 歸零、固定元素恢復可見、零殘留節點 |
| popup / options / result | 載入無任何 JS 錯誤 |

**捲動方式**是另一個獨立的驗證面。真實網站把捲動交給不同的東西，只看 `window` 就會有一半的頁面截不到：

| 頁面形態 | 實測結果 |
| --- | --- |
| 一般 `window` 捲動 | 12 幀、高度正確 |
| `html{overflow:hidden}`、捲動在 `body` | 識別為 `body`，10 幀、高度正確（±1px） |
| `html,body{overflow:hidden}`、捲動在內層容器 | 識別為 `inner`，10 幀、高度正確（±1px） |
| `overflow:hidden` 但內容溢出（modal 打開時的 body） | 使用者滾不動、程式可以，照樣完整擷取 |
| 捲動被自訂腳本接管（任何捲動都被推回頂端） | **明確報 `page-not-scrollable`，不產出任何檔案** |

最後一種是最惡劣的形態：`scrollHeight` 完全正常、看起來應該能滾，但每一道捲動指令都被無聲打回去。如果不驗證捲動有沒有真的生效，就會拍完十幾幀、拼出一張尺寸完全正確、內容卻是同一屏重複的圖。

還有一類頁面同樣要分開講：**捲動根本不是原生的**（`transform` / canvas 驅動，內容放在 `position: fixed` 的軌道上）。它的 `scrollHeight` 恆等於視口高、可捲動距離是 0，但內容明明有 7000px 排在視口底下。原生截圖路徑取不到那些內容——所以擴充功能會**明說**是這種情況，而不是默默交出一張只有一屏的圖。實測 `maxBottom=7000`、47 個元素超出一屏，判定為 `non-native`。

「捲不動」這三個字以前把四種完全不同的情況壓成同一句話，等於什麼都沒說。現在分成四檔，各自給對應的說明與建議：

| 結論 | 意思 |
| --- | --- |
| `scrollable` | 能捲動，只是還沒開始 |
| `blocked` | 有可捲動的內容，實際卻滾不動（被腳本接管） |
| `non-native` | transform / canvas 驅動的假捲動，原生路徑取不到 |
| `no-content` | 這一頁本來就只有一屏——不是故障，任何工具都只能截一屏 |
| `pdf-viewer` | 這是 PDF：內容由瀏覽器內建檢視器（外掛）繪製，不在 DOM 裡，任何基於捲動的方式都拿不到它的第二屏 |

**這套驗證抓出了五個「尺寸看起來對、內容其實是錯的」問題**，它們都不會拋錯，只會默默給你一張錯的圖：

- **`captureVisibleTab` 抓的是「視窗的活動分頁」，不是你指定的那一頁。** 全新安裝時 `onInstalled` 會自動打開設定頁，它就成了活動分頁——整張長圖拍的全是設定頁，尺寸還完全正確。現在每一幀都會先確認目標分頁在前台，不是就把它拉回來。
- **抓回來的畫面可能比量到的視口矮。** 模擬裝置指標、混合 DPI、高度取整都會造成這件事。照量到的值推進，每一幀都會漏掉一截內容，接縫處還會留下一條白邊。現在用第一幀**實測**的可用高度校正後續推進量，最後再把輸出裁到真正被覆蓋的高度。
- **內層滾動容器偵測太寬鬆。** 門檻原本是「能滾 200px」，結果頁面裡的側邊欄、程式碼區塊、聊天面板都可能被誤認成主滾動區——一旦誤判，`window` 永遠不會滾，整張長圖就是同一屏重複。現在門檻提高到一整個視口高、且必須佔據半個視口。
- **「視窗看起來能滾」不等於「視窗真的能滾」。** 這是上一條的孿生兄弟，也是「整頁只截到一屏」最常見的原因：`html { overflow: hidden }` 的頁面 `scrollHeight` 照樣很高，但 `window.scrollTo` 完全是空操作。原本的探測用 `scrollHeight - clientHeight` 當前提，於是永遠認為「window 能滾」，永遠不會去找真正在滾的那個元素。現在判斷權交給**實際試滾 1px**，而且四種可能性（`window` / `body` / 內層容器 / 全部失敗）都有對應的處理，連讀取位置與計算範圍都跟著實際的捲動方式走。
- **HUD 自己是 `position: fixed` 的元素，會被拍進圖裡。** 第一版在抓幀前把 HUD 用 `visibility` 藏起來、抓完再放回去——**這個做法是錯的**：`captureVisibleTab` 抓的是**合成結果**，不是 DOM。DOM 改完、消息返回，合成器可能還沒提交這一幀，於是抓到的仍是帶 HUD 的舊畫面；而且這是競態，只在輸掉的時候偶爾發生，最難查。現在非手動模式在**整個抓幀階段**把 HUD 收起來一次（手動模式因為 HUD 上有「完成」按鈕，只能逐幀切換，並補上合成等待）。進度在工具列徽章上照樣看得到。
- **整條流程從不檢查捲動有沒有真的生效。** 這是前面幾條的共同根源，也是最該修的一條：以前只要 `scrollTo` 回得來，就當作捲動成功了。現在每一幀都比對「要求滾到哪」與「實際滾到哪」，連續兩幀沒位移就中止並報 `page-not-scrollable`——**寧可失敗，也不要交出一張看起來沒問題的錯圖**。

順帶一個實測發現：headless Chromium 在這台 Windows 上的裝置像素比例是 **1.48–1.5**（系統縮放 150%），所以 1200px 寬的視口抓回來接近 1800px。這正是為什麼程式碼裡從不假設 `devicePixelRatio = 1`，而是每一幀都用「圖寬 ÷ 視口寬」現量一個比例出來——1.25、1.5、110% 這些值在真實環境裡都會遇到，猜錯的話整張長圖會被拉長或壓扁。

## 7. 檔案結構

```
snapscroll/
├─ manifest.json          MV3 清單（classic service worker）
├─ engine/                純邏輯，UMD，Node 直接可測
│  ├─ scroll-plan.js        每一幀滾到哪、留哪一段（接縫在這裡決定）
│  ├─ stitch-math.js        裝置像素比例、座標映射、捨入不漂移
│  ├─ paginate.js           長圖 → PDF 分頁
│  ├─ pdf-writer.js         零依賴 PDF 生成 + 自檢
│  ├─ filename.js           檔名模板與 Windows 清洗
│  └─ limits.js             畫布上限、分片策略
├─ common/                protocol / settings / history / i18n
├─ background/            service-worker、capture-controller、download
├─ injected/              注入頁面的代理（測量、滾動、HUD、框選）
├─ offscreen/             拼接、編碼、PDF 組裝
├─ ui/                    popup / options / result
├─ fixtures/              測試頁（含四種捲動形態：window / body / 內層容器 / 被腳本接管）
├─ tests/                 node --test
└─ tools/                 圖示、打包、測試頁伺服器、E2E
```
